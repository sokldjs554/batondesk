# 테스트 방법

> 모든 주문·고객·정책 데이터는 가상의 예시 쇼핑몰 "바통마켓"의 **예시 데이터**입니다.

## 준비

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
```

## 무엇을 어떻게 확인하는가

| 층 | 명령 | 모델 호출 | 무엇을 보는가 |
|---|---|---|---|
| 린트·타입 | `ruff check src tests scripts && ruff format --check src tests scripts && mypy` | 없음 | 코드 규칙, `mypy --strict` |
| 단위·통합 테스트 | `pytest` | 없음(대역) | 파이프라인이 설계대로 이어지는지 |
| 프롬프트 잠금 | `batondesk prompts check` | 없음 | 평가에 쓴 프롬프트 버전이 바뀌지 않았는지 |
| 평가 자료 | `python scripts/validate_eval_data.py`, `python -m batondesk.evals check-frozen` | 없음 | 형식, 중복, 근거 원문 일치, 평가용 동결 |
| 채점기 | `python -m batondesk.evals baselines --split test` | 없음 | 무행동 정책이 통과하지 못하는지 |
| 검색 | `python -m batondesk.evals retrieval --split test --gate eval_results/gate.json` | 없음 | 검색 품질이 기준 아래로 떨어지지 않았는지 |
| 화면 | `tests/e2e/run.sh` | 없음(규칙 엔진) | PC·모바일에서 실제 브라우저로 주요 흐름 |
| 배포 이미지 | `docker build -t batondesk . && docker run -p 8000:8000 batondesk` | 없음 | 이미지가 뜨고 상태·배포 정보·화면이 응답하는지 |
| 모델 호출 점검 | `python scripts/llm_smoke.py` | **있음** | 요청 형식이 맞는지(구조화 출력, 도구, 캐시) |
| 답변 품질 | `python -m batondesk.evals agent …` 등 (`docs/evaluation.md` 6절) | **있음** | 통과율, 인계 판단, 판정기 정확도 |

위 표에서 모델 호출이 "없음"인 줄은 전부 CI(`ci.yml`)에서 돈다. "있음"인 줄은 `eval-live.yml` 에서 돈다.

## 단위·통합 테스트가 보는 것 (`tests/`, 132건)

실제 모델을 부르지 않는다. 미리 정해 둔 응답을 돌려주는 대역(`QueueLLM`)으로 분기를 하나씩 밟는다.
**이 테스트는 답변 품질을 말해 주지 않는다.** "이런 모델 출력이 오면 시스템이 이렇게 움직인다"를 확인한다.

| 파일 | 확인하는 것 |
|---|---|
| `test_kb.py` | 문서 형식 검증, 절 단위 청크, 적용 기간 표시(현행/기간 한정/종료), 복합어 토큰화, 검색 모드 |
| `test_commerce.py` | 취소·반품 판정 규칙(기한의 경계 포함), **판정 규칙의 숫자가 지식 문서의 숫자와 같은지**, 다른 고객 주문 숨김, 고정 시계, 장애 재현과 재시도, 쓰기는 재시도하지 않음, 샌드박스 격리 |
| `test_tools.py` | 도구 스키마, 허용 목록, 주문번호 검증, 고객 범위, **쓰기 전 확인 코드(같은 턴 실행 거부, 지어낸 코드 거부, 한 번만 사용)** |
| `test_checks.py` | 사실 추출(금액·기간·날짜·시각), 판정을 주장 라벨에서 계산, 판정 모델 실패 시 규칙으로 닫힌 쪽 실패, 잘린 판정 출력 불신, 해결 판정의 규칙 우선 |
| `test_agent_graph.py` | 도구 반복, **근거에 걸린 초안의 보류 → 재작성 → 그래도 걸리면 인계**, flag/off 방식, 없는 인용 ID 제거, 거절·잘림·형식 오류·API 오류·반복 한도 → 안전한 인계, 대화 이력과 앞 턴 근거 전달, 화제 전환 시 검색, 주입한 초안도 같은 검사를 지남 |
| `test_service_api.py` | HTTP로 본 전체 흐름: 출처가 붙은 답변, **인계 수명 주기(대기 → 맡기 → 답장 → 종료), 인계 중 AI 침묵, AI에게 돌려주기**, 피드백이 판정을 덮어씀, **지표 정의대로의 집계**, SSE 진행 이벤트, 판정 API 단독 호출, 웹훅, 모델 없는 서버의 503, 저장된 기록은 읽기 전용 |
| `test_prompts.py` | 버전 로딩, 잠금이 수정된 버전을 잡아냄, 두 번째 버전부터 변경 이유 필수 |
| `test_evals.py` | **채점기가 옳은 답을 통과시키고 틀린 답을 떨어뜨리는지**, 양방향 문항 구성, 무행동 기준선, 문항 단위 구간, 오류 실행을 분모에서 뺌, 자료가 다른 실행끼리 비교 거부, 평가용 동결 |
| `test_eval_data.py` | 부품별 평가 자료 검증, 검색 게이트 |

## 화면 점검 (`tests/e2e/`)

`tests/e2e/run.sh` 가 규칙 엔진 서버(8811)와 모델이 꺼진 서버(8812)를 띄우고 Playwright로 1440×900과 390×844에서 다음을 눌러 본다. 항목은 118개다.

- 고객 화면: 문의 → 답변과 출처 칩 → 근거 원문 열기 / 주문 조회와 "예시 주문 시스템 조회 결과" 표시 / 응답 과정 보기
- 장애: 예시 주문 시스템을 오류로 바꾸고 문의 → 인계 카드와 대기 안내, 실행 기록의 도구 실패
- 인계: 상담원 연결 → 상담원 화면에서 맡기·답장 → 고객 화면에 상담원 답이 나타남 → 인계 중 AI는 답하지 않음 → 종료하면 입력이 닫힘
- 운영 화면: 지표와 정의 문구, 검토 대기, 프롬프트 버전 보기, 로그 필터
- 임베드: `/embed-demo` 에서 위젯을 열고 그 안에서 문의
- 오류 상태: 600자 초과, 종료된 대화, 끊긴 연결과 재시도, 모델이 꺼진 서버의 안내
- 모든 화면: 가로 스크롤 없음, 누르는 대상의 높이 40px 이상, 콘솔 오류 없음

규칙 엔진은 LLM이 아니어서 답이 단순하다. 여기서 보는 것은 화면의 동작이다. **실제 모델 응답이 화면에 나오는 모습과 저장된 상담 기록 열람은 아직 확인하지 못했다**(둘 다 실제 모델 실행이 있어야 한다).

사람이 볼 캡처는 2배 해상도로 다시 찍는다: `SCALE=2 SHOTS_DIR=docs/images/ui tests/e2e/run.sh`

## 손으로 해 보기

```bash
BATONDESK_LLM_MODE=scripted batondesk serve      # 규칙 엔진(LLM 아님). 화면에 그렇게 표시된다
ANTHROPIC_API_KEY=… batondesk serve              # 실제 모델
```

`http://localhost:8000` 에서 고객 화면 → 상담원 화면 → 운영 화면 순서로 본다.
