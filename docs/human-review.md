# 사람 검수 — 정답을 가리고 직접 매기기

> 모든 주문·고객·정책 데이터는 가상의 예시 쇼핑몰 "바통마켓"의 **예시 데이터**입니다.

**지금 상태: 검수 화면과 계산 도구는 준비되어 있고, 사람이 매긴 결과는 아직 없다.**
결과가 생기면 이 문서의 "결과" 절과 `docs/evaluation.md` 에 일치도를 싣는다. 그 전에는 "사람이 검수했다"고 말할 수 없다.

## 왜 하는가

이 저장소의 평가 문항, 정답 라벨, 채점 규칙, 실패의 분류는 모두 AI가 썼다. 그래서 지금의 수치는 다음을 가리지 못한다.

- 근거 판정기가 평가용의 어긋난 답 78건을 모두 잡은 것이 **판정기가 좋아서인지, 문항이 쉬워서인지**.
- AI가 붙인 정답 라벨이 **사람이 봐도 맞는지**.
- 글자 비교 채점이 통과시킨 응대가 **실제로 올바른지**. 실패한 응대는 전부 읽었지만 통과한 응대는 아무도 읽지 않았다.

다른 사람들의 상담 에이전트 평가를 조사해 보니, 평가가 가장 엄격한 저장소들은 이 자리에 사람을 둔다: 사람이 라벨한 표본 30~220건과 판정기–사람 일치도(일치율, Cohen's kappa)를 낸다. 낮게 나온 일치도도 그대로 적는다.

## 무엇을 매기는가

`/review` 화면이 평가용(test) 문항 64건을 정답 없이 보여 준다. 묶음은 세 개이고 하나만 해도 된다.

| 묶음 | 건수 | 보는 것 | 고르는 것 | 견주는 대상 |
|---|---:|---|---|---|
| 근거 판정 | 30 (맞음 15, 어긋남 15. 종류 18가지가 모두 한 번 이상) | 상담 정보, 근거, 대화, 답변 | 근거와 맞음 / 어긋남 | AI가 붙인 정답, 판정기 grounding-v1·v4 의 판정(3회 중 다수) |
| 해결 판정 | 18 (다섯 분류에 3~4건씩) | 대화 | 확인된 해결 / 가정된 해결 / 미해결 / 고객 답 대기 / 해당 없음 | AI가 붙인 정답, 판정기 resolution-v1 |
| 에이전트 응대 | 16 (채점이 통과시킨 것 8, 떨어뜨린 것 8) | 기준(기대한 행동과 이유), 참고 문서, 실제 모델의 응대 기록 | 올바른 응대 / 잘못된 응대 | 채점 규칙의 통과·실패 |

- 표본은 고정된 난수 씨앗으로 층화해 뽑았다(`scripts/build_human_review.py`). 판정기가 틀린 문항을 골라 넣거나 뺀 것이 아니다.
- 에이전트 응대는 평가용 실행 `20261126-124400-agent-test-test-a4-g4`(agent-v4 + grounding-v4)에서 뽑았다. 채점이 떨어뜨린 8건은 서로 다른 8문항에서 한 건씩이다.
- 화면에는 원래 문항 번호, 정답, 판정기의 결과가 나오지 않는다. 문항 순서는 묶음 안에서 섞었다.

## 하는 방법

1. <https://batondesk.onrender.com/review> 를 연다(또는 로컬에서 `batondesk serve` 후 `/review`).
2. 이름을 적고 묶음을 골라 문항마다 버튼 하나를 누른다. 숫자 키 1~5로도 고를 수 있다. 판단이 어려우면 가장 가까운 쪽을 고르고 메모를 남긴다.
3. 고른 답은 그 브라우저에만 저장된다. 닫았다가 다시 열어도 이어진다. 서버로 보내지 않는다.
4. "결과 보기"에서 결과를 복사하거나 파일로 저장한다.
5. 결과를 `data/human_review/labels/<이름>-<날짜>.json` 으로 저장소에 넣고 계산한다.

```bash
python -m batondesk.evals human data/human_review/labels/<파일>.json --out eval_results/human_review/<날짜>.json
```

근거 판정 30건이 20~30분, 전체 64건이 한 시간쯤 걸린다.

## 가린 채 한 검수가 되려면

- 정답표 `data/human_review/key.json` 은 공개 저장소에 있다. **마치기 전에 열어 보지 않는다.** 열어 봤다면 결과 파일의 `saw_answer_key` 를 `true` 로 고쳐 그 사실을 남긴다.
- `docs/evaluation.md` 의 6.3절·6.4절은 평가용 실패 문항과 그 원인을 이름으로 적고 있다. 에이전트 응대 묶음을 하기 전에 그 절을 읽었다면 완전히 가린 검수가 아니다. 그 사실도 결과에 적는다.
- 검수자가 한 명이면 "사람 사이의 일치도"는 알 수 없다. 사람도 틀린다.

## 결과를 읽는 법

- **사람 대 AI가 붙인 정답**: 사람이 라벨에 동의하는 비율. 낮으면 문항이나 라벨이 모호하다는 뜻이고, 그 문항으로 잰 판정기 정확도도 다시 봐야 한다.
- **사람 대 판정기**: 판정기가 사람과 얼마나 같은 판정을 하는가. 이것이 "환각 탐지 API 의 정확도"에 사람이 붙이는 근거다.
- **에이전트 응대**: 채점이 통과시켰는데 사람이 잘못됐다고 본 응대가 있으면, 통과율이 실제보다 높게 나오고 있다는 뜻이다.
- kappa 는 우연히 맞을 확률을 뺀 일치도다. 표본이 16~30건이라 폭이 넓다. 건수와 함께 읽는다.
- 표본은 평가용 전체가 아니다. 근거 판정 54건 중 30건, 해결 판정 36건 중 18건, 에이전트 실행 192건 중 16건이다.

## 결과

아직 없다.
