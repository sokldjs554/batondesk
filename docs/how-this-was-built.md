# 이 저장소가 만들어진 방식 — 누가 무엇을 했나

> 모든 주문·고객·정책 데이터는 가상의 예시 쇼핑몰 "바통마켓"의 **예시 데이터**입니다.

이 문서는 지원 서류를 쓸 때 사실과 다르게 쓰지 않도록, 실제로 일어난 일만 적는다.
자기소개서나 포트폴리오 문장은 여기 없다.

## 한 줄 요약

요청서 한 건을 받아 **AI 코딩 에이전트(Claude Code)가 조사·설계 초안·구현·테스트·실제 모델 평가·실패 분석·프롬프트 개선·문서화를 수행했다.**
저장소 주인은 요청서를 쓰고, 저장소를 만들고, 키를 시크릿에 넣고, 에이전트가 낸 설계 결정을 프로젝트의 결정으로 채택했다.
**주인이 코드를 직접 쓰거나, 테스트를 직접 실행하거나, 평가 결과를 직접 읽고 검수한 기록은 아직 없다.**

요청서의 표현은 "Codex 전달 메시지"였지만 실제로 작업한 도구는 Claude Code다. 서류에 도구 이름을 쓸 때 주의한다.

요청서에 담긴 판단(무엇을 평가할지, 무엇을 만들어 내지 말지)은 주인의 것이다.
"개발용과 평가용을 나눠라", "프롬프트를 바꾸면 같은 문항으로 전후를 비교하라", "받지 않은 평가를 받은 것처럼 쓰지 마라"는 요청서의 원칙이고, 이 저장소의 평가 절차는 그 원칙을 따른 것이다.

**설계 결정에 대해 정확히 적어 두면**: 각 결정의 초안, 버린 대안과의 비교, 문서는 AI 에이전트가 썼다. 주인은 그것을 프로젝트 책임자로서 채택했다.
"내가 설계안을 냈다"가 아니라 "에이전트가 낸 설계안을 내가 채택했다"가 일어난 일이다. 채택한 결정은 주인의 책임이므로, 각 결정의 이유와 버린 대안을 직접 설명할 수 있어야 한다(체크리스트 8번).
채택 선언(D1~D10) 뒤에 에이전트가 더한 결정(D11~D15: 실제 실행을 보고 바꾼 것들)은 주인이 아직 읽고 채택한 적이 없다.

작업 방식: 주 에이전트가 설계와 핵심 코드를 쓰고, 독립된 일(기존 저장소 조사, 제품 조사, 화면 구현, 판정기용 평가 자료 초안)은 하위 에이전트에게 맡긴 뒤 결과를 검토해 반영했다. 모든 커밋에 `Co-Authored-By: Claude` 가 붙어 있다.

에이전트가 **틀렸던 것**도 기록에 있다: 최종 응답을 JSON 출력 형식으로 받게 한 첫 설계(실제 API에서 도구 호출을 건너뛰어 바꿈), `A-D-CF-04` 실패의 원인 진단(프롬프트 문제로 봤지만 검색 문제였다), 근거 판정 v2 가 만든 회귀, 에이전트 v3 가 만든 회귀, 채점 규칙의 금지어, 커밋 `2e1a3fe` 에서 깨진 단위 테스트(다음 커밋에서 고침). `CHANGELOG.md` 와 `prompts/*/v*.yaml` 의 `changes` 에 있다.

에이전트가 **하지 못한 것**은 `docs/limitations.md` 의 첫 절에 있다(사람 검수, 사용자 평가).

## 3. 저장소 주인이 검토·재현한 일

**아직 없다.** 아래를 직접 해 본 뒤 날짜와 결과를 적으면 "검토·재현했다"고 말할 수 있다.
해 보지 않은 항목을 한 것처럼 쓰지 않는다.

테스트에 대해: 테스트 코드는 에이전트가 썼고, 에이전트가 자기 작업 환경에서 실행했다. 주인이 "테스트했다"고 말하려면 1·2번을 직접 실행해야 한다(10분 안쪽).
GitHub Actions의 CI 기록은 "저장소의 자동 검사가 통과했다"는 근거이지 "내가 테스트했다"는 근거가 아니다.

평가에 대해: 평가는 에이전트가 실행했고 결과도 에이전트가 읽었다. 주인이 "평가 결과를 검토했다"고 말하려면 4·5번을 해야 한다.

## 4. 서류에 쓸 때 지킬 것

- "내가 구현했다"가 아니라 "AI 에이전트에게 요구사항과 평가 원칙을 주고 구현·평가하게 했다"가 사실이다. 직접 한 것은 1절뿐이다.
- 설계는 "에이전트가 낸 안을 검토해 채택했다"고 쓴다. 채택한 결정은 이유를 설명할 수 있어야 한다.
- 테스트는 체크리스트 1·2번을 직접 실행하기 전에는 "내가 테스트했다"고 쓰지 않는다. 평가는 4·5번 전에는 "내가 검토했다"고 쓰지 않는다.
- 3절의 체크리스트를 수행한 항목만 "검토했다 / 재현했다"고 쓴다.
- **숫자를 쓸 때는 조건을 함께 쓴다.** 예: "평가용 64문항 × 3회, claude-haiku-5-5, 자동 채점, 사람 검수 없음".
- **쓸 수 없는 말**: "프롬프트 개선으로 정확도를 올렸다"(평가용에서 차이가 없었다), "환각을 100% 차단"(AI가 만든 틀린 답 78건과 주입 18건을 모두 잡았을 뿐이고, 검색이 틀려 나간 틀린 답은 못 잡았다), "해결률 N%"(실제 고객 대화가 없다), "사람 검수", "사용자 평가", "실서비스 운영", "팀 협업", "공개 데모를 실제 사용자가 썼다"(방문 기록이 없다).
- **쓸 수 있는 말의 근거**: 프롬프트 버전 비교를 같은 문항·같은 커밋에서 했다(`docs/evaluation.md` 6.2), 개선 효과가 없다는 결과를 그대로 보고했다, 실패를 읽어 원인이 프롬프트 밖(검색·판정기 입력·채점기)에 있음을 찾았다(6.1), 채점 규칙 오류를 찾아 수정 전후를 모두 남겼다(6.3), 판정기도 라벨된 자료로 따로 평가했다(4절, 5절), 지연·비용을 조건과 함께 쟀다(6.6).
- 검색 수치를 쓸 때는 조건을 함께 쓴다: 평가용 40문항, 5위 내 적중 77.5%, AI가 쓴 질의, 유의어 확장의 효과는 확인되지 않음.
- 벤더 제품에 대한 설명은 원문을 직접 확인한 뒤에 쓴다(`docs/research.md` 의 확인 수준 표시).
