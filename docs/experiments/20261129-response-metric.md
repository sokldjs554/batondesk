## 1. 추가한 지표

**대화당 전달 응답 수 = 집계 대상 대화에 저장된 고객용 AI 메시지 수 ÷ AI 관여 대화 수.** 운영 화면에서는 **대화와 응답 → 대화당 응답 수**로 표시한다.

- 분자는 `messages.role = ai`인 최종 저장 메시지를 센다. 답변, 되묻기, AI가 보낸 인계 안내를 포함한다.
- 분모는 기존 `conversations.ai_involved`와 같다. `turn_count >= 1`이거나 상담원 인계 이력이 있는 대화다. 고객이 바로 인계한 대화는 포함하고, 턴과 인계가 없는 빈 대화는 제외한다.
- 화면에만 보이는 초기 자동 안내, 보류된 초안, 모델 호출, 고객·상담원·시스템 메시지는 응답 수가 아니다.
- 출처 필터는 분자와 분모에 같은 대화 집합으로 적용한다. 해결률의 분모와는 다르다.
- 분모가 0이면 API는 `null`, 화면은 `—`다. 분모가 있고 전달 응답만 0이면 화면은 `0.00개`다.

`GET /v1/metrics/summary`에 다음 필드를 추가했다. 비율은 API에서 소수 넷째 자리, 화면에서 둘째 자리로 반올림한다.

```json
{
  "responses": {
    "delivered": 2,
    "denominator": 3,
    "per_conversation": 0.6667
  }
}
```

표 아래에는 실제 분자·분모와 함께 직접 인계 포함, 빈 대화 제외, 초기 안내·보류 초안·상담원·시스템 메시지 제외를 설명한다. 전체 정의는 [조사 기록 3절](../research.md#3-지표-정의--제품마다-다르다)에도 적었다.

## 4. 해석 범위

이 지표의 전달은 **서버에 최종 저장한 고객용 AI 메시지**를 뜻한다. 고객이 실제로 수신하거나 읽었는지 측정한 값은 아니다. 응답 수가 많다는 사실만으로 답변 품질이나 해결 성과가 좋다고 판단할 수 없다.

브라우저 검사는 규칙 엔진으로 화면과 집계를 확인했다. 실제 모델 답변 품질, 실제 고객 사용, 실제 운영 트래픽을 평가한 결과가 아니다. 브라우저 출처 검사는 규칙 엔진과 비어 있는 저장 기록 집합을 사용했고, live·recorded가 함께 있는 분자·분모 계산은 위 단위 검사에서 확인했다. 화면 검증 범위는 기록한 두 크기와 headless shell 실행에 한정된다. 프롬프트·동결 평가 자료는 수정하지 않았으며 held-out 평가를 실행하지 않았다.
